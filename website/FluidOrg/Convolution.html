Explorable explanations are interactive web essays that explain challenging technical ideas. Examples like this distill.pub article are inspiring but labour-intensive to create, especially for the kind of interactive graphics we might want to use to reveal how an algorithm works. How might Fluid help with this? One possibility is to use the built-in provenance-tracking infrastructure to allow an end-user to explore the relationships between the stages of the computational pipeline, using interactions like the ones shown below. This moves the implementation closer to being a self-explanatory artifact, rather than something that needs a separate, custom-crafted explanation. Enriched with integrated documentation, this could become a kind of literate execution.

Consider the following implementation of matrix convolution, an image processing technique which transforms an input matrix using a small matrix called a filter (or kernel) to apply effects like blurring or embossing. Toggle the data pane on the left to reveal the inputImage and filter; then mouse over the output (matrix on right) to see how the inputs are being used. As you will see, different cells in the output demand different cells in the input array and filter.

In particular, notice how only certain parts of the input are relevant to a given output cell. Can some of the irrelevant inputs be attributed to zeros in the filter? Which ones? Also notice how the demand varies as we approach the edge of the output image: because this implementation of convolution treats the input as though it were padded with zeros at the boundary, parts of the filter are irrelevant to the computation of output cells near the edge. Interactions like these would be more useful if we could show the actual computation involved for a given element, but even this simple extensional view already reveals interesting things about the implementation.

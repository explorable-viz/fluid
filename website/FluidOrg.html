With traditional print media, the figures, text and other content we consume are disconnected from the underlying data. With digital media, there is an opportunity to make visual artifacts that are connected to data and able to reveal those fine-grained relationships to an interested user. This would enable research outputs, news articles and other data-driven artifacts to be more transparent, self-explanatory and explorable — a nice goal but one which would be very laborious to implement by hand for each output. Fluid is a programming language for authoring computational outputs that come with these transparency features built-in.

When the figures below have finished loading, click on the button in the margin to reveal a view of the underlying data set. Records are shown only if any of their fields are used somewhere in either of the two figures. Any records that are completely unused — as well as any unused fields of other records, which are greyed out — are called inert. By hiding inert data, the reader is already restricted to a view containing only the relevant data.

Interactive data provenance

By tracking how data flows through a computation, we can do a lot more than just hide away or grey out unused data. Try some of the following:

  • Mouse over the data in the nuclearCap column. As you move around in that column, various points in the scatter plot are highlighted in blue: these are the outputs which consume the data element under your mouse. For any nuclearCap value your mouse is over, you will notice that 3 other values are also highlighted. These are the related inputs for that value: the other inputs which were needed to compute the highlighted scatter plot point. In this case there are 4 values (one for each country) which are mutually related, because each point in the scatter plot represents a year and the nuclear capacity in that year of 4 countries is added together to compute the x-coordinate of the point.
  • Now try the same with the nuclearOut column. In this case the related inputs for a given input value also include the coal, gas and petrol output for that country; that's because these data are also used to compute the bar segments in the stacked bar chart on the left.

Computational transparency as infrastructure

The key idea of Fluid is that these interactivity features, that allow an interested user to explore the relationships between inputs and outputs, are provided automatically. The language runtime keeps track of dependencies and then surfaces that dependency information via UI affordances automatically added to the output; the author of the content can simply expresses their visualisation or other output as a pure function of the input.
